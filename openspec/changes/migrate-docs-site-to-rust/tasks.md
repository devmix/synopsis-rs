# Tasks: migrate-docs-site-to-rust

Read first: `proposal.md`, `design.md`, and `openspec/config.yaml`. This change
moves the Docusaurus 3.10.2 site from the old project
(`/mnt/local/secure/projects/devmix/synopsis/site` — copy source, **read-only,
never modify it**) into `site/` and rewrites ALL of its content to document the
Rust implementation. Every task is self-contained for a fresh agent (~100k
context): goal, exact file scope, dependencies, machine-checkable acceptance,
and named references all fit in the body.

## Rules (summary — full detail in design.md)

- **Copy source (read-only).** `/mnt/local/secure/projects/devmix/synopsis/site`
  — task 1.1 copies from it; no other task reads it except as a style reference.
- **Sources of truth for content (read before writing):** the 14 contract
  specs `openspec/specs/{mcp-contract,cli-surface,data-schema,config-format,
  db-storage,embedding,entity-extraction,hybrid-search,knowledge-graph,
  llm-client,parsing-and-chunking,pipeline,vector-index,utils}/spec.md`,
  `README.md`, `AGENTS.md`, `docs/adr/`, `.github/workflows/{ci,release}.yml`,
  `workspace/configs/README.md`. Each task names the exact files to read.
- **Gates (every task, run in `site/`):**
  - G1: `npm run typecheck` → 0 errors
  - G2: `npm run build` → success. `onBrokenLinks: 'throw'` fails the build on
    any broken internal link — the site must be link-consistent after every task.
- **Go-era residue sweep (every content task, over its own files):**
  `git grep -Pin 'golang|cgo|sqlite-vec|vec0|mcp-go|goreleaser|golangci|\bgo test\b|\bgo build\b' -- <task files>` → **0**.
  (Revision 2026-09-05, task 2.2: `-P` PCRE with `\b` word boundaries — the
  old case-insensitive `go test`/`go build` patterns false-positived on the
  substrings inside `cargo test`/`cargo build`. Revision 2026-09-05, task 3.1:
  plain `|` alternation — under `-P` (PCRE) the BRE-style `\|` is NOT an
  alternation and the sweep silently matched nothing.)
- **Cross-links:** link only to pages that EXIST at the time of the task. For a
  page created by a later task, use plain text (no link). G2 enforces this.
- **Sidebar:** autogenerated from the docs folder structure (`sidebars.ts` →
  `autogenerated`); NO manual sidebar edits. Page order = frontmatter
  `sidebar_position` (existing positions listed per task; new pages get the
  positions assigned here).
- **Scope discipline:** modify ONLY the files in the task's Scope. No refactors,
  no reformatting of unrelated files. **No new npm dependencies.**
- **Language:** English only. Keep the existing doc voice (concise,
  scannable, tables for flags/keys).
- **Concept depth (design D10, user directive 2026-09-05):** concept pages
  (`site/docs/concepts/`) stay at the WHAT/WHY model level — no schema dumps
  (table names with column lists/types, index names, migration file paths).
  Those live in `reference/database-schema.mdx` (task 7.2) and the developer
  docs. Passing prose mentions of a table/column for context are fine.
