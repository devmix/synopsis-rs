# utils-crate Specification (delta)

## ADDED Requirements

### Requirement: Общий крейт утилит

Крейт `crates/utils` — дом для кросс-кратных хелперов, не принадлежащих доменному крейту; лист зависимости (не зависит от внутренних крейтов, любой крейт может использовать). Модуль `temporal` — единственный источник работы с датой/временем в проекте; рукописные реализации календарной математики и парсинга временных меток запрещены.

#### Scenario: Единственная точка входа
- **WHEN** любому крейту нужна конвертация/парсинг/форматирование дат
- **THEN** используется `utils::temporal`, а не локальные хелперы

### Requirement: Temporal API поверх jiff

Модуль temporal тонко оборачивает jiff: `now_rfc3339`, `format_rfc3339(SystemTime)`, `format_backup_stamp(SystemTime)` (шаблон `%Y-%m-%dT%H-%M-%S-<ms>` UTC для имён VACUUM-снимков), `normalize_to_rfc3339(&str)` (принимает RFC3339 и SQLite-лейаут `YYYY-MM-DD HH:MM:SS` как UTC), `parse_epoch_seconds(&str) -> Option<i64>`. Некорректный/пустой ввод → None без паник.

#### Scenario: Два принимаемых формата
- **WHEN** на вход поданы `2026-08-25T10:00:00Z` и `2026-08-25 10:00:00`
- **THEN** оба нормализуются в один RFC3339-вывод / один epoch-секунды результат

#### Scenario: Мусорный ввод
- **WHEN** на вход подана пустая строка или не-дата
- **THEN** возвращается None, паники нет

### Requirement: Байт-в-байт совместимость миграции

Миграция четырёх рукописных мест (search enrich/rerank, ingestion parsers/backup) сохраняет выходные строки идентичными: таблица паритета нормализации (13 кейсов), граничные случаи свежести ±60с и round-trip тесты переезжают в crates/utils; потребительские тесты остаются зелёными без изменений ассертов.

#### Scenario: Паритет таблицы нормализации
- **WHEN** 13 кейсов таблицы нормализации прогоняются через utils::temporal
- **THEN** результаты совпадают с зафиксированными при hand-rolled реализации
