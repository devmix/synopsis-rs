# Proposal — native-seam-spikes

## Why

До массового переписывания модулей (каждый — отдельный change, исполняет свежий ИИ-агент) нужно снять риск с трёх нативных швов: SQLite+FTS5 через rusqlite, ONNX Runtime через `ort` (преемник неактивного onnxruntime-rs), ANN-движок (usearch vs lance при RAM-бюджете ноутбука и 1M×1024). Шов MCP-транспорта закрыт ранее решением scaffold D8 (rmcp over Streamable HTTP; доказан round-trip тестами parity-harness) — отдельного спайка не требует. Провал любого шва должен стать известен до того, как ИИ начнёт писать модули против него. Спайки дают также зафиксированные решения для design последующих change'ов и формат фикстур паритетных проверок.

## What Changes

- Временный crate `crates/spikes` (3 bin-таргета S1–S3) — прототипы, удаляются после записи решений
- Решения фиксируются в ADR: `docs/adr/000X-*.md` (один на каждый спайк): выбор + измерения + отклонённые альтернативы
- Формат фикстур паритета: бинарный дамп векторов `vectors.bin` (layout, endianness, порядок по chunk_id) — контракт между Go-оракулом и parity-harness
- Зафиксированная конфигурация ANN (M/efConstruction/efSearch/квантизация) на основе замеров S3
- **Non-goals:** прикладное поведение модулей; экспорт vectors.bin из Go-репо (внешняя задача оракула, выполняется позже вместе с первым модульным change'ом); MCP-транспорт сверх решения D8 scaffold (rmcp Streamable HTTP — зафиксирован и доказан, спайк не нужен)

## Impact

- Только новый репо: `crates/spikes/*`, `docs/adr/*`; scaffold-артефакты не затрагиваются
- Внешний вход: fixture knowledge.db, генерируемый СУЩЕСТВУЮЩИМИ инструментами оракула (`load-test --scale ...`), без изменений кода Go
- Выход для последующих change'ов: ADR по каждому шву + конфигурация ANN + формат vectors.bin
