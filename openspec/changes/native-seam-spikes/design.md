# Design — native-seam-spikes

## Context

См. proposal.md (Why). Жёсткие ограничения из openspec/config.yaml: ноутбук 16 ГБ; N до 1M × 1024-dim с disk-backed/квантованным индексом; реализацию пишут свежие ИИ-агенты без памяти предыдущих сессий — значит решения спайков должны жить в файлах, а не в чате.

## Goals / Non-Goals

**Goals:** GO/NO-GO по каждому из трёх швов (S4 закрыт решением D8 scaffold — см. ревизию в tasks.md) + зафиксированные ADR; выбор ANN-движка и его конфигурации по измерениям; формат фикстур паритета (vectors.bin) как контракт между Go-оракулом и parity-harness.

**Non-goals:** прикладное поведение модулей; экспорт vectors.bin из кода Go-репо (внешняя задача оракула, позже); MCP-транспорты сверх паритета с оракулом.

## Decisions

### D1. Один временный crate `crates/spikes` с bin-таргетами s1..s3

Создаётся этим change'ом и удаляется после записи ADR (задача 5.x). Прототипы не портируются в боевые crate'ы — переиспользуемая логика переписывается заново там, где она нужна.
**Альтернатива:** отдельный crate на спайк (отклонено: ритуал ради одноразового кода).

### D2. Фикстура S3 — синтетические 1M×1024 f32 с фиксированным seed

Сравнение ANN-движков — вопрос механики индекса, а не семантики корпуса; синтетика воспроизводима и не ждёт внешнего экспорта. Ground truth (brute force) считается внутри спайка.
**Риск/митигация:** геометрия реального корпуса может отличаться → перед change'ом реализации crate'а `vectors` измерения S3 повторяются на реальной фикстуре (явная задача в том change').

### D3. Решения — ADR в `docs/adr/000X-<slug>.md`

Формат каждого ADR: Вопрос / Варианты / Измерения / Решение / Отклонённые альтернативы. Это единственный устойчивый источник решений для агентов без памяти; design последующих change'ов ссылается на номера ADR.

### D4. Формат vectors.bin (контракт оракул ↔ harness)

```
magic    4 B   "SYNX"
version  u32 LE = 1
dim      u32 LE
count    u64 LE
rows     [u32 LE chunk_id][f32 LE × dim] × count, по возрастанию chunk_id
```

Самоописуемый, стримится/mmap'ится без JSON-оверхеда на ~4 ГБ.
**Альтернатива:** Arrow/Parquet (отклонено: лишняя зависимость harness до выбора движка; пересмотреть при росте фикстур).

### D5. Справочные эмбеддинги S2 — self-consistency как основной гейт

Основной гейт: два запуска дают бит-идентичные векторы + идентичность входов (тот же model.onnx, tokenizer.json из реестра onnx.yaml, ORT 1.28 по конфигу). Опциональный mean-cos ≥ 0.999 против Go-дампа — НЕ блокирующий: паритет поиска всё равно гейтится recall@k на уровне поиска (см. spec data-schema), мелкие fp-разхождения рантаймов допустимы и измеряются там.
**Причина:** дамп из Go требует внешней задачи в оракуле и не должен тормозить спайк.

### D6. Инициализация схемы и механизм миграций (решения человека, 2026-08-18)

Rust всегда строит свою БД с нуля: ОДИН init-каталог `migrations/1-init/up.sql` со squashed DDL финального v5-состояния (выводится механически из схемы fixture — дамп sqlite_master минус явный список Go-artifacts `_schema_migrations` и vec0-shadow; кросс-чек семантики против 001..005 оракула). Механизм = `rusqlite_migration` 2.6 (`from-directory`, include_dir на compile-time); состояние схемы = `PRAGMA user_version` — единственный источник истины (= 1 после init; будущие миграции добавляются нумерованными каталогами `<id>-<slug>/up.sql`, shipped не редактируются, forward-only). Go-совместимость отслеживания НЕ поддерживается: `_schema_migrations` не создаётся; legacy knowledge.db от Go не открывается, не апгрейдится, данные не мигрируются. Fixture — dev-time ground truth (read-only) для дифференциальных проверок.
**Альтернативы (отклонены человеком):** копировать 001–005 оракула как есть (реплей мёртвой истории на чистой БД); bridge/double-write `_schema_migrations` + user_version (совместимость явно не требуется).

## Risks / Trade-offs

- **Синтетика S3** (см. D2) — митигация зашита как задача будущего change'а, а не пожелание.
- **Сетевые зависимости спайков:** модель bge-m3 int8 (~2,3 ГБ) и ONNX Runtime скачиваются существующим механизмом onnx.yaml; в CI позже это станет кэшируемым артефактом.
- **Фикстура 0.1 требует собранный Go-бинарь оракула** (`make build` в ../synopsis) и его существующие инструменты генерации данных — без изменений кода оракула.
