# knowledge-graph Delta

## MODIFIED Requirements

### Requirement: Кросс-доменный пайплайн линковки

Пайплайн применяет методы по порядку конфигурации: `equals` (точное совпадение имён), `expression` (CEL-правила), `llm` (LLM-сравнение пары через OpenAI-совместимый клиент). Каждый метод идемпотентен: повторная линковка не создаёт дубликатов (ON CONFLICT DO NOTHING через EntityLinkDao). Флаг `linker.disabled` отключает LLM-метод. LLM-метод для каждой пары: загружает контекст чанков обеих сущностей (до 3 текстов на сущность), рендерит шаблоны system/user (загрузка из `prompts_path`, embedded-fallback), вызывает LLM-клиент со структурированным выводом, парсит решение `{same_entity, confidence, reasoning}`, создаёт link только при confidence ≥ `llm_confidence_threshold` (method='llm', evidence=reasoning, confidence клампится в [0,1]); решение кэшируется в app_kv по хэшу (пара сущностей + хэши шаблонов) — повторный вызов той же пары не обращается к LLM. Сбой вызова/парсинга одной пары не прерывает пайплайн (фиксируется в результатах).

#### Scenario: equals-линковка
- **WHEN** две сущности разных доменов имеют одинаковые нормализованные имена
- **THEN** создаётся cross-domain link; повторный прогон не дублирует

#### Scenario: expression-линковка
- **WHEN** CEL-правило онтологии истинно для пары сущностей
- **THEN** создаётся link с типом/приоритетом правила

#### Scenario: LLM-линковка выше порога
- **WHEN** LLM валидно отвечает same_entity=true и confidence ≥ порога
- **THEN** создаётся link method='llm' с evidence=reasoning; решение записано в кэш

#### Scenario: LLM ниже порога
- **WHEN** confidence решения ниже `llm_confidence_threshold`
- **THEN** link не создаётся; решение кэшируется

#### Scenario: Кэш решений
- **WHEN** пара уже имеет кэшированное решение (те же хэши шаблонов)
- **THEN** LLM не вызывается; используется кэшированное решение

#### Scenario: Отказ одной пары
- **WHEN** вызов LLM или парсинг ответа для пары завершается ошибкой
- **THEN** ошибка фиксируется в результатах; пайплайн продолжает остальные пары

#### Scenario: LLM-стаб
- **WHEN** пайплайн доходит до метода llm
- **THEN** выполняется реальная LLM-линковка пары (стаб из change graph заменён: контекст → шаблоны → вызов клиента → решение); существующие линки не затрагиваются

#### Scenario: Отключение линкера
- **WHEN** `linker.disabled=true`
- **THEN** llm-метод исключён из пайплайна; equals/expression работают
