# vectors — Proposal

## Why

Крейт `vectors` — последний отсутствующий блок базового яруса (D1: `config, db, vectors → …`). Поиск по смыслу невозможен без ANN-индекса: оракул использовал vec0 brute-force внутри SQLite, что не масштабируется на целевой корпус (N=1M × 1024-dim ≈ 4 ГБ f32 не помещается в RAM ноутбука 16 ГБ). Решение по движку и конфигурации уже снято спайком и зафиксировано в ADR 0003 (GO: LanceDB, IvfHnswSq u8-SQ, гейты p95 < 10 ms / recall@10 ≥ 0.95 / RSS ≤ ~2 GB) — этот change реализует его в боевом крейте. Векторы НЕ читаются из старого vec0 — пересобираются из текста чанков (решение 2026-08-18).

## What Changes

- Новый крейт `crates/vectors`: trait-контракт ANN-индекса (`VectorIndex`) + реализация на LanceDB (`lancedb = "0.37"`, ADR 0003): создание/открытие таблицы, стриминговая вставка `(chunk_id, vector)`, построение индекса IvfHnswSq, kNN-поиск top-k с `_distance`, удаление по chunk_id, перечисление id, персистентность в `data_dir`.
- **Каскадная согласованность SQLite ↔ LanceDB (решение человека 2026-08-21):** векторы строятся по чанкам; при удалении чанка удаляются связанные векторы; обе БД всегда синхронны. Контракт: упорядоченный каскад (векторы до строк чанков), примитивы reconciliation (перечисление chunk_id индекса для сверки с SQLite), толерантность потребителя поиска (join по существованию чанка).
- Формат фикстур `vectors.bin` (SYNX, design D4 native-seam-spikes): reader/writer в крейте `vectors`; закрытие TODO в `parity-harness`.
- Конфигурация: `VectorIndexConfig` в крейте (дефолты ADR 0003; efSearch/nprobes — runtime-настройки по митигации ADR 0003) + опциональная секция `vectors:` в config preset.
- Бенчмарк-гейты ADR 0003 повторяются на реальной фикстуре + полный прогон N=1M (открытые вопросы ADR 0003 №2 — явные задачи этого change'а).

**BREAKING (контрактное, заранее одобрено):** секция `vectors:` в config preset — аддитивное расширение замороженного config-format (решение человека 2026-08-21). Аддитивно и обратно совместимо: пресеты без секции получают дефолты ADR 0003; Go-оракул игнорирует неизвестные ключи.

## Capabilities

### New Capabilities
- `vector-index`: контракт ANN-индекса — жизненный цикл (build/open/persist/rebuild/drop), kNN-поиск, каскадное удаление по chunk_id и протокол синхронизации с SQLite, формат фикстур SYNX, производственные гейты.

### Modified Capabilities

(нет — существующие спеки не меняются; data-schema уже фиксирует «пересборку из текста чанков» как требование к этому крейту)

## Impact

- **Код:** новый `crates/vectors` (tier-0 D1: без внутренних зависимостей — на вход готовые `(chunk_id, vector)`, запросный путь не грузит модель эмбеддингов); `crates/config` (+секция preset, опционально); `crates/parity-harness` (замена TODO на загрузчик SYNX); корневой `Cargo.toml` (workspace-пин lancedb).
- **Зависимости:** lancedb 0.37 / lance 10 (тяжёлая транзитивная база arrow/datafusion/object_store — риски MSRV, кросс-компиляции 5 CI-таргетов и размера бинаря снимаются feasibility-задачей до основной реализации).
- **Замороженные контракты:** config-format расширяется аддитивно (см. BREAKING выше); data-schema/mcp-contract/cli-surface не затрагиваются. Паритет подтверждается дифференциально: recall@k против brute-force ground truth на общей фикстуре vectors.bin + гейты ADR 0003.
- **Потребители (будущие change'и):** `search` (гибридный поиск через trait), `ingestion`/`graph` (каскад при удалении документов), `cli` (wiring конфига).

## Non-goals

- Гибридный поиск (FTS5+RRF) — change `search`.
- Вызов эмбеддинг-модели из крейта vectors (в т.ч. авто-пересборка векторов по расписанию) — оркестрация в `ingestion`/будущем GC; здесь только примитивы.
- Реализация GC-job'а планировщиком — примитивы reconciliation даёт этот change, сам job — позже.
- LLM/API-провайдер эмбеддингов (решение человека 2026-08-21: позже, выбор провайдера через конфиг) — вне этого change'а.
- Экспорт vectors.bin из Go-репо — внешняя задача оракула (native-seam-spikes proposal).
