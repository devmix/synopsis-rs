# Cross-Domain Linking

The same real-world thing is often mentioned in several domains: a product appears in HR documents (compensation for product managers), in IT documents (the system itself), and in product documents (customer-facing materials). Each domain extracts its own entity for it — until linking says *these are the same* and connects them.

Entity links are the **only edges that cross domain boundaries** in the knowledge graph: search stays domain-scoped, traversals cross only across explicit links, and every link carries the proof of how it was made.

## Linking methods

The methods and their order are configured in the `<cross-domain-links>` block of `global.xml` (`<methods><method>`). The pipeline applies the methods **in configuration order**, and each method is **idempotent** — re-linking never creates duplicates (inserts use `ON CONFLICT DO NOTHING`), so re-running is always safe.

| Method | What it does |
|--------|--------------|
| `equals` | **Name matching**: exact match of normalized names between entities of different domains, guarded by a minimum word count (`<equals><min-words>`, e.g. 2) so one-token names don't produce false matches. |
| `expression` | **Rule-based**: evaluates CEL rules from the ontology against candidate pairs. A pair for which a rule is true gets a link with the rule's relation type and priority. |
| `llm` | **LLM-based identity resolution**: an OpenAI-compatible LLM compares the pair with context drawn from both entities' chunks and decides whether they denote the same entity. Links only when the decision clears the confidence threshold. |

The `linker.disabled` configuration flag disables the `llm` method — with it set, `equals` and `expression` still work.

### CEL expressions

The `expression` method evaluates **CEL expressions** through the `cel` crate. Each rule in `<expressions><expression>` carries a `<name>`, `<description>`, `<priority>`, a `<where>` condition, and a `<relation-type>`:

```xml
<expressions>
    <expression>
        <name>same-product</name>
        <description>Link product entities with the same name between domains</description>
        <priority>80</priority>
        <where>A.type == 'product' &amp;&amp; A.type == B.type &amp;&amp; A.name == B.name</where>
        <relation-type>same_entity</relation-type>
    </expression>
</expressions>
```

The evaluation context provides contract functions to inspect the pair: `facts(entity)`, `has_fact(entity, key, value)`, `chunks(entity)`, `chunk_contains(entity, text)`, `neighbors(entity)`, and `path_exists(from, to, max_depth)` — heavy indexes behind them are loaded lazily only when a rule actually uses them. See [Knowledge Graph](./knowledge-graph#cel-linkers) for the full function table.

### The LLM method

For each pair, the `llm` method:

1. **Loads chunk context** for both entities — up to 3 texts per entity.
2. **Renders the prompt** — a system and a user template, rendered with **minijinja**. Templates are loaded from the `prompts_path` configuration (the shipped overrides live under `workspace/configs/prompts/entity-linker/{system,user}.tmpl`); a missing override file silently falls back to the embedded default.
3. **Calls the LLM** with structured output and **parses the decision** `{same_entity, confidence, reasoning}`.
4. **Creates a link only when `confidence` ≥ the threshold** (`<llm-confidence-threshold>`): `method='llm'`, `evidence=reasoning`, confidence clamped to [0, 1]. A decision below the threshold creates no link.

A call or parse failure for one pair does **not** abort the pipeline — the error is recorded in the results and the remaining pairs are processed.

#### Decision cache

Every LLM decision is **cached in the application key-value store, keyed by a hash of the entity pair plus the template hashes**. A repeat call for the same pair does not hit the LLM — the cached decision is used instead. Because the template hashes are part of the key, changing the prompt templates invalidates the cached decisions and re-runs the comparison.

#### The LLM client

The comparison goes through Synopsis' OpenAI-compatible client (`crates/llm`), configured by the `linker.llm` section of the YAML preset (`api_base_url`, `model_name`, `api_key`, `temperature`, `seed`, `max_tokens`, `timeout_ms`, `max_retries`, `response_format`):

- the request is `POST {api_base_url}/chat/completions` with `model`, `messages` (system + user), `temperature`, `seed`, `max_tokens`; authentication is a Bearer token from `api_key` (an empty key sends no Authorization header);
- **structured output** — `response_format: json_object` sends `{"type":"json_object"}`; `response_format: json_schema` sends a nested `json_schema` object with a name (default `"llm_output"`) and the schema supplied by the caller;
- **retries** — transient failures are retried up to `max_retries` times with exponential backoff and jitter: HTTP 429 and 5xx are retryable, network errors and timeouts are retryable; a valid response with empty content is an explicit *non-retryable* error; exhausting the attempts is an explicit error carrying the last failure's reason.

## Provenance

Every stored link records **how it was made**:

- **method** — `expression`, `equals`, or `llm`;
- **confidence** — for `llm` links the model-reported value, clamped to [0, 1];
- **evidence** — a human-readable explanation (for `llm` links, the model's reasoning).

`get_entity_links` returns all links for an entity with this provenance intact — an agent can weigh a link, or simply ignore low-confidence LLM links, if it needs to.

## When linking runs

Linking is a **post-processing step of the ingestion pipeline** — not a separate command:

1. documents are ingested (parse, chunk, embed, NER, entities, facts);
2. **link building runs** over the entities, if the `cross-domain-links` configuration is present.

The run is **incremental and event-driven**: when a run creates or updates entities, the pipeline enqueues an `entity:link` event (identity = document id), and the background worker links only those candidates against the rest of the dataset — never the document's full entity set. A per-pair linking error is logged and skipped without aborting the run.

## Using links

- **`get_entity_links`** — see the links and provenance for one entity.
- **`get_entity_relations`** — traverse the graph across domains: the traversal may cross a boundary only where an actual entity link exists between the current node and its neighbor; ordinary fact edges never do.
- **`get_entity_dossier`** — includes the entity's cross-domain links alongside approved facts, sources, and related entities.
