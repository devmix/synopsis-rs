# Quickstart

From a prebuilt archive (or source) to a searchable MCP.

## 1. Get the binary

### Option A — prebuilt archive

Prebuilt archives are published as Gitea Releases on `v*` tags for the 5 supported targets:

| Target | Triple |
| --- | --- |
| Linux amd64 (fully static) | `x86_64-unknown-linux-musl` |
| Linux arm64 | `aarch64-unknown-linux-gnu` |
| Linux arm64 (musl) | `aarch64-unknown-linux-musl` |
| Windows amd64 | `x86_64-pc-windows-gnu` |
| macOS arm64 | `aarch64-apple-darwin` |

Each archive bundles the stripped binary, the README, `workspace/configs/`, and the `edtech` demo dataset (ontology + content). Download the archive for your platform, extract it, and run the `synopsis` binary.

### Option B — build from source

The toolchain is pinned to Rust **1.96.0** in `rust-toolchain.toml`; rustup installs it automatically on the first cargo command. SQLite (with FTS5) is compiled in-tree (bundled), so there are no system dependencies:

```bash
cargo build --release     # → target/release/synopsis
```

## 2. Bootstrap the runtime state

Network access is needed on first run: the ONNX runtime library and the default embedding model are downloaded by the binary per `workspace/configs/onnx.yaml` (verified by URL + size + SHA-256).

```bash
synopsis onnx-runtime install   # download the ONNX runtime per workspace/configs/onnx.yaml
synopsis model download         # download the default embedding model
```

## 3. Start the server

```bash
synopsis serve
```

The server listens on port **8080** with the `default` preset. Without `--config`, the config is auto-searched: `<exeDir>/workspace/configs/` → parent directory → CWD. `--preset NAME` selects `config.{NAME}.yaml`; `--dataset NAME` overrides the configured dataset.

On startup, `serve` performs a startup reconcile (enqueueing a diff into the document job queue) and starts a file watcher; a background worker processes the queue and builds the index. Pass `--no-initial-sync` to skip the startup reconcile.

Endpoints:

| Endpoint | Method | Purpose |
| --- | --- | --- |
| `/mcp` | POST | MCP over Streamable HTTP (primary transport) |
| `/sse` | GET | legacy HTTP+SSE transport (client connection) |
| `/message` | POST | legacy message endpoint (`sessionId` query parameter) |
| `/health` | GET | JSON health status |

Verify that it is up:

```bash
curl http://localhost:8080/health
```

## 4. Connect an MCP client

Point any MCP client at `http://localhost:8080/mcp` (Streamable HTTP) or `http://localhost:8080/sse` (legacy HTTP+SSE). The server exposes exactly 12 tools, all read-only (facts are restricted to `approved` status):

`search`, `catalog_overview`, `catalog_documents`, `catalog_entities`, `search_entities_by_type`, `search_facts`, `get_document_context`, `get_chunk_by_id`, `get_fact_by_id`, `get_entity_dossier`, `get_entity_relations`, `get_entity_links`

The `search` tool performs a hybrid query: lexical (FTS5) and semantic (vector) results are fused with Reciprocal Rank Fusion and reranked by recency/authority. Full parameters and result shapes are documented in the [MCP tools reference](./reference/mcp-tools).
