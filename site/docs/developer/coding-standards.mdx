# Coding Standards

The project is idiomatic Rust. Every crate opts into the workspace lint baseline in the root `Cargo.toml`, and the CI gate runs clippy with `-D warnings` — so **any warning fails the build**; at the gate, warn and deny are the same thing.

## Workspace lints

| Lint | Level | What it enforces |
|---|---|---|
| `missing_docs` (rustc) | `deny` | Every public API item is documented — a missing doc comment fails compilation |
| `unsafe_code` (rustc) | `forbid` | No `unsafe` blocks anywhere; the frozen stack has no unsafe requirements |
| `clippy::all` | `warn` | The default clippy baseline, made explicit |
| `clippy::unwrap_used` | `warn` | No `.unwrap()` — fail the gate instead |
| `clippy::expect_used` | `warn` | No `.expect()` — same as `unwrap_used` |

Test modules may opt out locally where an assertion makes the failure explicit anyway:

```rust
#[cfg(test)]
mod tests {
    #![allow(clippy::unwrap_used)]
    // ...
}
```

That is the sanctioned opt-out — it lives on the test module, not on the crate.

## Error handling

- **Result-based.** Fallible operations return `Result<T, E>` with a typed error; errors propagate with `?` and gain context at the boundary that owns it.
- **No panics for expected errors.** `panic!` is for genuine invariant violations, never for recoverable conditions.
- **`unsafe` is forbidden.** The FFI seams (usearch via cxx, ONNX via `ort`) are managed by their bindings; if native-seam work ever needs a relaxation, it is a per-crate, explicitly justified exception — not a default.

## Dependencies

**No new dependencies without an OpenSpec change.** The stack is frozen in `openspec/config.yaml`, and the shared dependency palette lives in the root `Cargo.toml` — adding a crate is a contract-level decision, not an implementation detail.

## Gates

There is no Makefile — plain cargo commands are the whole build system:

```bash
cargo fmt --check                          # formatting, must be clean
cargo clippy --all-targets -- -D warnings  # lint gate, any warning fails
cargo test                                 # full workspace suite, ~20 s warm
```

CI runs all three on every push — see [CI/CD](./ci-cd).
