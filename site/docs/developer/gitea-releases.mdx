# Gitea Releases

The release pipeline lives in `.github/workflows/release.yml`. It is triggered by **push of a tag matching `v*`** (for example `v0.1.0`) and, in a single job, cross-compiles the binary for all five supported targets, packages a per-platform archive for each, writes a checksum file, and publishes a Gitea Release.

## Why it is a single job

The workflow runs on a **self-hosted Gitea runner**, and the runner has **no artifact service** — no work product can be passed between jobs. So the whole pipeline (five builds, five packages, checksum, publish) runs sequentially on one `ubuntu-latest` runner:

- the 5-target build lives in `release.yml` and **only there** — the dev CI (`ci.yml`) stays fast;
- the build runs first and the publish second: if the cross-build fails, **nothing is published** — fix and re-push the same tag to retry;
- the job requests `contents: write` because it creates the Gitea Release; every other step only reads the repository.

Do not "upgrade" the Gitea-fork actions to the standard GitHub actions — they break on the Gitea runner.

## Pipeline steps

1. **Checkout** with full history (`fetch-depth: 0`) so the tag — and thus the version — is available.
2. **Install the pinned toolchain** — `dtolnay/rust-toolchain@1.96.0` (must match `rust-toolchain.toml`) with all five target stds up front; no clippy/rustfmt components are needed.
3. **Cache cargo artifacts** — `Swatinem/rust-cache@v2` caches `~/.cargo` and `./target`, keyed by the installed rustc version, so it runs after the toolchain step.
4. **Install cargo-zigbuild** — `cargo install --locked cargo-zigbuild`; `--locked` pins the exact dependency set from its Cargo.lock, and the binary lands in `CARGO_HOME`, which the cache step already covers.
5. **Install Zig 0.16.0** — `mlugg/setup-zig@v2`, the C toolchain for every target.
6. **Build-and-package loop** — for each of the five targets: `cargo zigbuild --release --target <t>`, strip with `zig objcopy --strip-all` (one command handles all three object formats: ELF, PE/COFF, Mach-O), then rebuild a clean `stage/` directory and archive it as `dist/synopsis_<version>_<name>.<ext>`.
7. **Generate checksums** — `SHA256SUMS.txt` over all archives in `dist/`.
8. **Publish** — the Gitea Release (below).

## The five targets

| Target triple | Platform | Archive (v0.1.0 example) |
|---|---|---|
| `x86_64-unknown-linux-musl` | Linux amd64 | `synopsis_0.1.0_linux_amd64.tar.gz` — **fully static** |
| `aarch64-unknown-linux-gnu` | Linux arm64 | `synopsis_0.1.0_linux_arm64_gnu.tar.gz` |
| `aarch64-unknown-linux-musl` | Linux arm64 | `synopsis_0.1.0_linux_arm64_musl.tar.gz` |
| `x86_64-pc-windows-gnu` | Windows amd64 | `synopsis_0.1.0_windows_amd64.zip` |
| `aarch64-apple-darwin` | macOS arm64 | `synopsis_0.1.0_darwin_arm64.tar.gz` |

**windows-gnu, not msvc** — Zig cannot link the MSVC ABI from a Linux host, so the Windows target uses the GNU ABI.

## What ships in an archive

Each archive bundles exactly:

- the stripped `synopsis` binary (`synopsis.exe` on Windows);
- the root `README.md` (it doubles as the end-user documentation shipped with the binary);
- `workspace/configs/` — presets, `onnx.yaml`, prompt templates;
- `workspace/datasets/edtech/ontology/` — the `edtech` demo ontology.

Deliberately excluded: the ONNX runtime library and the model weights (gitignored runtime artifacts the binary downloads per `onnx.yaml`) and the demo corpus.

## Publishing

The release is published with **`akkuman/gitea-release-action@v1`**, the Gitea-compatible fork of the GitHub release action, uploading `dist/synopsis_*.tar.gz`, `dist/synopsis_*.zip`, and `dist/SHA256SUMS.txt`:

- the body is deliberately empty (manual release); the name defaults to the tag;
- a dash-suffixed tag (`vX.Y.Z-rc*`) is marked as a **prerelease**;
- `NODE_OPTIONS: --experimental-fetch` covers runners with Node < 18, where `fetch` is not built in (a no-op on newer Node).

## Release flow

```
git tag -a v0.1.0 && git push origin v0.1.0
      │
      ▼
release.yml (single job): 5× zigbuild → strip → package → SHA256SUMS.txt
      │
      ▼
Gitea Release with the 5 archives + checksum file
```
