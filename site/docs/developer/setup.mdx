# Development Setup

## Dev environment

| Requirement | Version | Notes |
|---|---|---|
| Go | 1.25.5 | `go.mod` declares `go 1.25.5`; CI pins the same version |
| C toolchain | gcc or clang | **CGO is mandatory** — `go-sqlite3` compiles SQLite (FTS5 + sqlite-vec) into the binary; `CGO_ENABLED=0` will fail |
| Make | any recent | All day-to-day commands are Makefile targets |
| Zig | 0.14+ | Optional — C toolchain for cross-compilation (see [Cross-compilation](#cross-compilation)) |
| golangci-lint | v2.12 | No separate install — `make lint` runs the pinned version via `go run ...@v2.12`, matching CI |

If you only build and run for your own platform, Zig is not needed.

### Installing Zig (optional)

```bash
# Linux (any 0.14+ works locally; releases build with Zig 0.16)
curl -L "https://ziglang.org/builds/zig-linux-x86_64-0.14.0.tar.xz" \
  | tar xfJ - -C /tmp/
sudo mv /tmp/zig-linux-x86_64-0.14.0/zig /usr/local/bin/zig
zig version

# macOS (Homebrew)
brew install zig
```

## Quick start

```bash
make build      # CGO build of bin/synopsis
make sync       # build + run the ingestion pipeline
make run        # build + start the MCP server on :8080
```

See the [Quickstart](../quickstart) for what each stage does and how to make a first `search` call.

## Makefile targets

| Target | What it does | Command equivalent |
|---|---|---|
| `make build` | Build for the current platform | `CGO_ENABLED=1 CGO_CFLAGS="-DSQLITE_ENABLE_FTS5 -DSQLITE_ENABLE_VEC -O2" go build -o bin/synopsis ./cmd/app/` |
| `make run` | Build + start the MCP server | `./bin/synopsis --config configs/config.default.yaml serve` |
| `make sync` | Build + run the sync pipeline | `./bin/synopsis --config configs/config.default.yaml sync` |
| `make rebuild` | Build + clear the DB and re-ingest everything | `./bin/synopsis --config configs/config.default.yaml sync --rebuild` |
| `make test` | All tests with the race detector | `go test -race ./...` |
| `make test-coverage` | Tests + HTML coverage report | `go test -coverprofile=coverage.out -race ./...` → `coverage.html` |
| `make lint` | golangci-lint static analysis (pinned to v2.12, matching CI) | `go run github.com/golangci/golangci-lint/v2/cmd/golangci-lint@v2.12 run ./...` |
| `make vet` | `go vet` checks | `go vet ./...` |
| `make clean` | Remove build artifacts | `rm -rf bin/ coverage.out coverage.html` |
| `make build-all` | Cross-compile all five platforms | all platform targets below |

Model management (`model list/download/delete/info/benchmark`) and ONNX Runtime management are not Makefile targets — run them directly against the binary:

```bash
./bin/synopsis model list
./bin/synopsis model download bge-small-en-v1.5
./bin/synopsis model benchmark            # all installed models
./bin/synopsis onnx-runtime status
```

See [CLI Reference](../reference/cli#model) and [Model Management](../guides/model-management).

## Cross-compilation

All cross-compilation targets use **Zig as the C toolchain**: `zig cc` acts as a drop-in replacement for `gcc`/`clang` and can target any platform without separate sysroots.

| Target | Zig target triple | GOOS / GOARCH | Output binary |
|---|---|---|---|
| `make build-linux-amd64` | `x86_64-linux-gnu` | `linux` / `amd64` | `bin/synopsis-linux-amd64` |
| `make build-linux-arm64` | `aarch64-linux-gnu` | `linux` / `arm64` | `bin/synopsis-linux-arm64` |
| `make build-windows-amd64` | `x86_64-windows` | `windows` / `amd64` | `bin/synopsis-windows-amd64.exe` |
| `make build-macos-amd64` | `x86_64-macos` | `darwin` / `amd64` | `bin/synopsis-macos-amd64` |
| `make build-macos-arm64` | `aarch64-macos` | `darwin` / `arm64` | `bin/synopsis-macos-arm64` |

Example (what the Makefile does under the hood):

```bash
CGO_ENABLED=1 \
CC="zig cc -target aarch64-linux-gnu" \
CXX="zig c++ -target aarch64-linux-gnu" \
GOOS=linux GOARCH=arm64 \
go build -o bin/synopsis-linux-arm64 ./cmd/app/
```

Details worth knowing:

- **SQLite header symlink.** The vec0 bindings include `#include "sqlite3.h"`. Locally the Makefile (and `scripts/build.sh`) create a temporary `sqlite3.h` → `sqlite3-binding.h` symlink from the `go-sqlite3` module and pass it through `CGO_CFLAGS=-I...`; in releases the GoReleaser before hook does the same ([CI/CD](./ci-cd#release-workflow-releaseyml)).
- **macOS specifics.** macOS has no separate `libresolv`/`libdl`/`libpthread` (they live in `libSystem`), so the Darwin targets point Zig at the parseable stubs in `scripts/darwin-stubs/` first, then at Zig's bundled SDK, and link with `-Wl,-undefined,dynamic_lookup`. Builds pass `-ldflags=-w` (no DWARF) so Go skips its `dsymutil`/`strip` step, which would otherwise invoke a host GNU `strip` that cannot process Mach-O.
- **Release parity.** The release workflow cross-builds all five targets from a single `ubuntu-latest` runner using the same Zig approach (via GoReleaser, not this script) — see [CI/CD](./ci-cd#cross-compilation). Keep the CGO_CFLAGS defines in sync between the Makefile and `.goreleaser.yaml`.

## Troubleshooting

- **`CGO_ENABLED=0` build failure** — CGO is required; the Makefile always sets `CGO_ENABLED=1`
- **`vec0` extension not found** — sqlite-vec must be compiled into go-sqlite3 (build tags in `go.mod`)
- **Embedding dimension mismatch at startup** — delete `data/knowledge.db` and re-ingest, or pass `--auto-rebuild-vectors`
- **Domain XML not found** — `paths.global_config_path` must point at the ontology directory containing `domains/*.xml`
- **Cross-compilation fails** — check `zig version` (0.14+) and that the target triple in the Makefile matches the platform

The full failure catalog: [Troubleshooting](../guides/troubleshooting).
