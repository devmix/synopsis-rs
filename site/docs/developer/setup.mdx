# Development Setup

## Toolchain

| Requirement | Version | Notes |
|---|---|---|
| rustup | any recent | Installs the pinned toolchain automatically |
| Rust | 1.96.0 | Pinned in `rust-toolchain.toml` — rustup installs it on the first cargo command in the repo |
| Zig | 0.16.0 | Optional — cross-compilation only (see [Cross-compilation](#cross-compilation)) |
| Node.js | >= 20 | Only for building the docs site in `site/` |

There is no C toolchain requirement for a native build: SQLite (with FTS5) is compiled in-tree via rusqlite (bundled), so a build cannot silently lack FTS5 support.

## Quick start

```bash
cargo build --release   # → target/release/synopsis
cargo test              # full workspace suite, ~20 s warm; no services or network needed
```

Run the server with `cargo run -p cli -- serve` — config is auto-searched (`<exeDir>/workspace/configs/` → parent directory → CWD), the default preset is `default`, and the MCP server listens on port 8080. The full first-run walkthrough (runtime install, model download, serving, connecting an MCP client) is in the [Quickstart](../quickstart).

## Quality gates

CI runs all three; a change is not green without all of them:

| Gate | Command | What it enforces |
|---|---|---|
| Formatting | `cargo fmt --check` | must be clean |
| Lints | `cargo clippy --all-targets -- -D warnings` | any warning fails the build (workspace lints: `missing_docs = "deny"`, `unsafe_code = "forbid"`) |
| Tests | `cargo test` | full workspace suite, ~20 s warm, no services or network |

Narrowing the scope:

```bash
cargo test -p <crate>                      # a single crate
cargo test -p <crate> -- <TestNameFilter>  # a single test
```

Coverage is `cargo llvm-cov --workspace --html` — measure-first, no gates. Details: [Coding Standards](./coding-standards) and [Testing](./testing).

There is no Makefile — the plain cargo commands above are the whole build system.

## Cross-compilation

All cross-builds use `cargo zigbuild` with Zig 0.16.0 as the C toolchain (install the helper once: `cargo install --locked cargo-zigbuild`):

```bash
cargo zigbuild --release --target <t>
```

The five supported targets (the CI cross-build matrix):

| Target triple | Platform | Notes |
|---|---|---|
| `x86_64-unknown-linux-musl` | Linux amd64 | fully static artifact |
| `aarch64-unknown-linux-gnu` | Linux arm64 | |
| `aarch64-unknown-linux-musl` | Linux arm64 | musl |
| `x86_64-pc-windows-gnu` | Windows amd64 | gnu, not msvc — Zig cannot link MSVC ABI from a Linux host |
| `aarch64-apple-darwin` | macOS arm64 | |

The release workflow cross-builds all five from a single runner — see [CI/CD](./ci-cd).

## Building the docs site

The docs site is a Docusaurus 3.10.2 project in `site/` — it is NOT part of the Rust workspace build and NOT built in CI (deployment is manual):

```bash
cd site
npm install     # the lockfile is intentionally not committed — a fresh clone has no lockfile, so npm ci would fail
npm run start   # dev server with live reload
npm run build   # → site/build/
```

See `site/README.md` for the full list of commands and the manual-deployment note.

## Runtime bootstrap

The binary downloads its own runtime dependencies per `workspace/configs/onnx.yaml` (URL + size + SHA-256 verified) — on a fresh machine, the first two commands after a build set it up:

```bash
synopsis onnx-runtime install   # download the ONNX runtime library
synopsis model download         # download the default embedding model
```

Then `synopsis serve`. Full details: [Installation](../guides/installation) and [Model Management](../guides/model-management).
