# Installation

Synopsis compiles to a **single self-contained binary** — SQLite (with FTS5) is compiled in-tree (bundled), so there is no C toolchain requirement and no system dependency. At runtime the binary needs only a writable directory for its state; the ONNX runtime library and the embedding model weights are downloaded by the binary on demand, verified against the registry.

There are two ways to get the binary:

| Path | When to use it |
| --- | --- |
| [Prebuilt archive](#prebuilt-archives) | Default — one download, no toolchain |
| [Build from source](#build-from-source) | You want the bleeding edge or a custom target |

## Prebuilt archives

Prebuilt archives are published as **Gitea Releases on `v*` tags** for the 5 supported targets:

| Target | Triple | Notes |
| --- | --- | --- |
| Linux amd64 | `x86_64-unknown-linux-musl` | fully static artifact |
| Linux arm64 | `aarch64-unknown-linux-gnu` | |
| Linux arm64 | `aarch64-unknown-linux-musl` | musl |
| Windows amd64 | `x86_64-pc-windows-gnu` | gnu, not msvc — Zig cannot link MSVC ABI from a Linux host |
| macOS arm64 | `aarch64-apple-darwin` | |

Each archive is named `synopsis_<version>_<name>.<ext>` and bundles the stripped binary, the README, `workspace/configs/` (presets, `onnx.yaml`, prompt templates), and the `edtech` demo ontology. A `SHA256SUMS.txt` is published alongside the archives.

Download the archive for your platform, extract it, and run the `synopsis` binary:

```bash
tar xzf synopsis_0.1.0_linux-amd64.tar.gz   # or unzip on Windows
./synopsis --version
```

## Build from source

The toolchain is pinned to Rust **1.96.0** in `rust-toolchain.toml`; rustup installs it automatically on the first cargo command in the repository.

```bash
git clone https://github.com/devmix/synopsis-rs.git && cd synopsis-rs
cargo build --release     # → target/release/synopsis
```

Verify the binary:

```bash
./target/release/synopsis --version
```

There is no Makefile — the plain cargo commands are the whole build system. `cargo test` runs the full workspace suite (~20 s warm, no services or network needed).

## Cross-compilation with Zig

Building for another platform uses **Zig as a portable C toolchain** via `cargo-zigbuild` — no per-platform sysroots or SDKs needed. Install the pieces once (Zig **0.16.0**, plus the cargo helper):

```bash
cargo install --locked cargo-zigbuild
```

Then build any of the five targets (the same matrix the release workflow uses):

```bash
cargo zigbuild --release --target <t>
```

| Target triple | Platform | Notes |
| --- | --- | --- |
| `x86_64-unknown-linux-musl` | Linux amd64 | fully static artifact |
| `aarch64-unknown-linux-gnu` | Linux arm64 | |
| `aarch64-unknown-linux-musl` | Linux arm64 | musl |
| `x86_64-pc-windows-gnu` | Windows amd64 | gnu, not msvc |
| `aarch64-apple-darwin` | macOS arm64 | |

For example, `cargo zigbuild --release --target aarch64-unknown-linux-musl` works from a Linux amd64 host without any ARM toolchain. The release workflow cross-builds all five targets on a single runner and publishes the archives — see [Gitea Releases](../developer/gitea-releases).

## Bootstrap the runtime state

Network access is needed on first run: the binary downloads its own runtime dependencies per `workspace/configs/onnx.yaml`, verifying each download (URL + size + SHA-256 where the registry provides a checksum).

```bash
synopsis onnx-runtime install   # download the ONNX runtime library (~24 MB) → workspace/onnxruntime/
synopsis model download         # download the default embedding model → workspace/models/
```

Then start the server:

```bash
synopsis serve                  # port 8080, preset "default"
```

## Where things live

All runtime state lives under a single `workspace/` directory that the binary creates and manages:

```
workspace/
├── configs/                  # tracked: presets, onnx.yaml, prompt templates
├── datasets/<name>/          # per-dataset: ontology/, content/, state/ (knowledge.db + vectors)
├── db/cache/cache.db         # global cache DB (shared across datasets)
├── models/                   # downloaded model weights
└── onnxruntime/              # downloaded ONNX runtime library
```

Only `configs/` and the `edtech` demo dataset are tracked in the repository; everything else is created and downloaded at runtime. The [Workspace Layout](../concepts/workspace-layout) page covers the tree in detail, including what is gitignored.
