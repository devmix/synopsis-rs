# Configuration

Synopsis is configured by a single YAML **preset** file (`config.{preset}.yaml`), an external **model registry** (`onnx.yaml`), and per-dataset **XML ontologies** (not YAML). The repository ships `workspace/configs/` with the default preset, the registry, and the prompt templates.

## Config file resolution

The binary resolves the preset path in this order:

1. **`--config PATH`** — used verbatim if given; the auto-search is skipped.
2. **Preset auto-search** — otherwise the binary looks for `config.{preset}.yaml` (default preset: `default`), first relative to the executable's directory, then the CWD:
   1. `<exeDir>/workspace/configs/config.{preset}.yaml`
   2. `<exeDir>/config.{preset}.yaml`
   3. `<parent(exeDir)>/config.{preset}.yaml`
   4. `<parent(exeDir)>/workspace/configs/config.{preset}.yaml`
   5. `<CWD>/workspace/configs/config.{preset}.yaml`
   6. `<CWD>/config.{preset}.yaml`

   If nothing exists, the binary falls back to the relative `workspace/configs/config.{preset}.yaml` and fails with a load error naming that path.

In short: `<exeDir>/workspace/configs/` → parent directory → CWD. The executable path is not symlink-resolved.

`--preset NAME` selects `config.{NAME}.yaml` (default: `default`). Example with a custom preset:

```bash
cp workspace/configs/config.default.yaml workspace/configs/config.prod.yaml
synopsis --preset prod serve
```

`--dataset NAME` overrides the configured dataset (`dataset.name` in the preset) for a single run — the per-dataset artifacts (ontology, content, knowledge DB, vectors) resolve under `<workspace_dir>/datasets/<NAME>/`.

## Global flags

Global flags are parsed **before the subcommand** and apply to every subcommand (`serve`, `queue`, `db`, `model`, `onnx-runtime`, `load-test`):

| Flag | Description |
| --- | --- |
| `--config PATH` | Path to the configuration file (skips auto-search) |
| `--preset NAME` | Preset name; the binary searches for `config.{NAME}.yaml` (default: `default`) |
| `--dataset NAME` | Dataset name; overrides `dataset.name` from the config |
| `--version` | Print the version and exit |

```bash
# Use an explicit config and point at a specific dataset
synopsis --config workspace/configs/config.default.yaml --dataset edtech serve
```

## Walkthrough of `config.default.yaml`

Unknown keys do not break startup. Unknown values of string fields that are not validated at parse time (`logging.level`/`format`/`output`, `chunking.strategy`, `response_format`, `archive_format`, `source.type`, `attribute.type`) are kept as-is rather than rejected.

### `database`

```yaml
database:
  pragma:
    mmap_size: "268435456"   # 256MB
    journal_mode: WAL
    synchronous: NORMAL
    cache_size: "-64000"     # 64MB
```

| Key | Type | Default | Behavior |
| --- | --- | --- | --- |
| `database.pragma` | map of string → string | `{}` | PRAGMA overrides applied on connection. WAL journal with normal synchronous is a good balance for a single-writer workload; the mmap and cache sizes speed up reads on large corpora. |

The knowledge-DB **path is not configurable**: it is derived from `workspace_dir` + `dataset.name` as `<workspace>/datasets/<name>/state/db/knowledge.db`. The legacy `database.path` key from the pre-restructure layout is accepted but ignored.

### `embeddings`

```yaml
embeddings:
  mode: "local"
  local:
    model_name: "bge-small-en-v1.5"  # auto-download
  api:
    base_url: "http://localhost:1234/v1"
    api_key: ""
    model_name: "text-embedding-3-large"
    max_retries: 3
    timeout_ms: 30000
```

| Key | Type | Default | Behavior |
| --- | --- | --- | --- |
| `embeddings.mode` | string | — | `"local"` (in-process ONNX Runtime) or `"api"` (OpenAI-compatible HTTP endpoint). Any other value is rejected at validation. |
| `embeddings.local.model_name` | string | `""` (empty → `models.default` in `onnx.yaml`) | Model name from the `onnx.yaml` registry; **downloaded automatically on first use** into `workspace/models/`. An empty name selects `models.default` from the registry; the model's dimension and file locations come from the registry entry. |
| `embeddings.api.base_url` | string | required in api mode | Base URL of the embeddings endpoint. |
| `embeddings.api.api_key` | string | `""` | Bearer token; empty if not required. |
| `embeddings.api.model_name` | string | required in api mode | Model to request from the API. |
| `embeddings.api.max_retries` | integer | 3 | Retries after an initial failure. |
| `embeddings.api.timeout_ms` | integer | 30000 | HTTP request timeout in milliseconds. |
| `embeddings.auto_rebuild_vectors` | boolean | `false` | Config-file equivalent of the `--auto-rebuild-vectors` CLI flag: on a detected dimension mismatch the vectors are rebuilt automatically instead of failing. |

**Shipped-preset deviation (not a bug):** `config.default.yaml` deliberately names `bge-small-en-v1.5` instead of the frozen `bge-m3-int8` — faster local testing on the small model. The dimension (384 vs 1024) comes from the `onnx.yaml` registry entry, not the preset; the preset file and `workspace/configs/README.md` document the choice.

Switching to a model with a different dimension — the registry entry's `vector_dim` in `onnx.yaml` — requires rebuilding the vectors — see [Troubleshooting](./troubleshooting).

### `ingestion`

```yaml
ingestion:
  chunking:
    markdown:
      strategy: "hybrid"
      max_chunk_size: 8192
      overlap_size: 100
      min_section_size: 500
    json:
      text_fields: [ "description", "title", "details" ]
      combine_fields: true
  ner:
    llm:
      api_base_url: "http://192.168.1.7:1234/v1"
      model_name: "openai/gpt-oss-20b"
      api_key: "sk-none"
      temperature: 0.01
      seed: 12
      max_tokens: 4096
      response_format: "json_schema"   # or "json_object"
      timeout_ms: 120000
      max_retries: 3
  batch_size: 100
  max_retries: 3
  resolver:
    similarity_threshold: 0.85
```

| Key | Type | Default | Behavior |
| --- | --- | --- | --- |
| `ingestion.chunking.markdown.strategy` | string | `"headers"` | One of `headers`, `fixed`, `hybrid`; tolerant — an unrecognized value does not break startup. |
| `ingestion.chunking.markdown.max_chunk_size` | integer | 1000 | Maximum characters per chunk. |
| `ingestion.chunking.markdown.overlap_size` | integer | 100 | Overlap between consecutive chunks in characters. |
| `ingestion.chunking.markdown.min_section_size` | integer | 500 | Minimum section size before it is split. |
| `ingestion.chunking.json.text_fields` | list of string | `["description", "title", "wikitext", "html"]` | Which JSON object fields carry text. |
| `ingestion.chunking.json.combine_fields` | boolean | `false` | Merge all indexed fields into a single chunk per object. |
| `ingestion.chunking.json.max_objects` | integer | 0 (unlimited) | Limit on the number of objects processed. |
| `ingestion.ner.disabled` | boolean | `false` | When `true`, no NER runs at all. |
| `ingestion.ner.llm.api_base_url` | string | `""` | OpenAI-compatible API endpoint for the LLM NER provider. |
| `ingestion.ner.llm.api_key` | string | `""` | Bearer token; empty if not required. |
| `ingestion.ner.llm.model_name` | string | `""` | Model identifier to call. |
| `ingestion.ner.llm.temperature` | float | 0.0 | Sampling temperature (0.0 for determinism). |
| `ingestion.ner.llm.max_tokens` | integer | 0 | Maximum tokens per response. |
| `ingestion.ner.llm.seed` | integer | 0 | Random seed for deterministic sampling. |
| `ingestion.ner.llm.response_format` | string | `"json_object"` | `"json_object"` or `"json_schema"` (full JSON Schema in the request body; requires API support); tolerant. |
| `ingestion.ner.llm.timeout_ms` | integer | 60000 | HTTP request timeout in milliseconds. |
| `ingestion.ner.llm.max_retries` | integer | 3 | Retry attempts for transient errors (429, 5xx). |
| `ingestion.batch_size` | integer | 100 | How many documents are processed per ingest batch. |
| `ingestion.max_retries` | integer | 3 | Maximum automatic re-processing attempts for a problematic task by the background worker; after exhaustion the task gets `error` status in the `queue_tasks` queue. |
| `ingestion.resolver.similarity_threshold` | float | 0.8 | Jaro-Winkler similarity threshold for merging duplicate entity names. |

See [Ingestion](./ingestion) for how the chunking and NER settings drive the pipeline.

```yaml
linker:
  disabled: false

```

| Key | Type | Default | Behavior |
| --- | --- | --- | --- |
| `linker.disabled` | boolean | `false` | When `false` (and the ontology's `global.xml` declares `<method>llm</method>`), the LLM cross-domain entity linker is active. |
| `linker.llm.*` | (same shape as `ingestion.ner.llm`) | | `api_base_url`, `api_key`, `model_name`, `temperature`, `max_tokens`, `seed`, `response_format`, `timeout_ms`, `max_retries` for the linking LLM. |

### `search`

```yaml
search:
  rrf_k: 20
  lexical_top_k: 20
  semantic_top_k: 20
  final_top_k: 10
  enable_lexical: true
  enable_semantic: true
  timeout_ms: 10000
  deprecated_boost: 0.2
  official_boost: 1.5
  recent_boost: 1.2
  recent_days: 90
  authority_boost:
    policy: 1.5
    regulation: 1.3
    default: 1.0
```

| Key | Type | Default | Behavior |
| --- | --- | --- | --- |
| `search.rrf_k` | integer | 20 | The Reciprocal Rank Fusion constant; a lower value increases rank sensitivity. |
| `search.lexical_top_k` | integer | 20 | Candidate pool size for the lexical (FTS5) leg. |
| `search.semantic_top_k` | integer | 20 | Candidate pool size for the semantic (vector) leg. |
| `search.final_top_k` | integer | 10 | Merged top-K returned to callers. |
| `search.enable_lexical` | boolean | `true` | Enable the lexical leg. If **both** legs are disabled, both are force-enabled. |
| `search.enable_semantic` | boolean | `true` | Enable the semantic leg (same force-enable rule). |
| `search.timeout_ms` | integer | 10000 | Per-search timeout in milliseconds. |
| `search.deprecated_boost` | float | 0.2 | Boost penalty for deprecated content. |
| `search.official_boost` | float | 1.5 | Boost for official sources. |
| `search.recent_boost` | float | 1.2 | Boost for recent content (within `recent_days`). |
| `search.recent_days` | integer | 90 | Recency window in days for `recent_boost`. |
| `search.authority_boost` | map of string → float | `{"default": 1.0}` | Authority-based boost factors keyed by authority name (document type). |

See [Searching](./searching) for the fusion and reranking behavior.

### `vectors`

```yaml
vectors:
  engine: "usearch"
  usearch:
    max_segment_vectors: 1000000
    compaction_stale_threshold: 30
    search_threads: 4
```

The whole section is optional — an absent section resolves to the engine defaults.

| Key | Type | Default | Behavior |
| --- | --- | --- | --- |
| `vectors.engine` | string | `"usearch"` (absent) | The ANN engine. Only `"usearch"` is accepted; `"lance"` is rejected with an explicit error naming the removal, and any other value fails the parse. |
| `vectors.dim` | integer | 1024 | Vector dimensionality of the index. |
| `vectors.m` | integer | 16 | HNSW graph degree M. |
| `vectors.ef_construction` | integer | 100 | HNSW candidate list size during index build. |
| `vectors.num_partitions` | integer | 256 | Number of IVF partitions (coarse-quantizer centroids). |
| `vectors.nprobes` | integer | 32 | IVF partitions probed per query. |
| `vectors.ef_search` | integer | 200 | HNSW candidate list size during query. |
| `vectors.quantization` | string | `"bf16"` | Scalar quantization: one of `"u8"`, `"i8"`, `"f16"`, `"bf16"`, `"f32"`; an unrecognized value fails the parse. |
| `vectors.usearch.max_segment_vectors` | integer | 1000000 | Maximum vectors per segment after compaction; must be > 0. |
| `vectors.usearch.compaction_stale_threshold` | integer | 30 | Stale-vector percentage (1–100) that triggers compaction. |
| `vectors.usearch.search_threads` | integer | 4 | Number of parallel search threads; must be > 0. |

The usearch index is disk-backed (mmap) and scalar-quantized; the two-layer persistence (RAM layer + WAL segments + compaction) is described in [Vector Rebuild](../concepts/vector-rebuild).

### `auto_update`

```yaml
auto_update:
  enabled: true
  debounce_seconds: 1
  watch_sources: true
  initial_sync: true    # full source scan on startup; false to skip
  retry_failed:
    enabled: true
    poll_interval_seconds: 60
```

| Key | Type | Default | Behavior |
| --- | --- | --- | --- |
| `auto_update.enabled` | boolean | `true` (absent section) | Enable filesystem monitoring. A **missing section** is materialized with `enabled = true`; a present section is honored as parsed (`enabled: false` is not overwritten). |
| `auto_update.debounce_seconds` | integer | 30 | Minimum interval between re-indexings in seconds. |
| `auto_update.watch_sources` | boolean | `true` | Watch all sources. **Presence semantics**: absent → `true`; an explicit `false` is honored. |
| `auto_update.initial_sync` | boolean | `true` (absent section) | Run a full source scan (startup reconcile) on startup. `serve --no-initial-sync` also skips it. |
| `auto_update.retry_failed` | object | `{ enabled: true, poll_interval_seconds: 60 }` | Background re-processing of problematic documents. |
| `auto_update.retry_failed.enabled` | boolean | `true` | Enable the worker's retry sweep of the `queue_tasks` queue. |
| `auto_update.retry_failed.poll_interval_seconds` | integer | 60 | Poll interval for the `queue_tasks` queue in seconds. |

See [Job Queue](../concepts/job-queue) for the queue states and the `queue status` / `queue reset-retries` commands.

### `scheduler`

```yaml
scheduler:
  jobs:
    orphan_cleanup:
      enabled: true
      interval_seconds: 300   # run every 5 minutes
```

| Key | Type | Default | Behavior |
| --- | --- | --- | --- |
| `scheduler.jobs` | map of name → job | `orphan_cleanup` registered | Named jobs, each with `enabled` (boolean) and `interval_seconds` (integer). The scheduler runs in singleton mode: overlapping executions of the same job are dropped, which protects SQLite from concurrent writers. `orphan_cleanup` (removes data for documents that disappeared from the sources) is registered by default — **disabled** with a 3600 s interval unless explicitly configured. |

### `logging`

```yaml
logging:
  level: "debug"
  format: "console"
  output: "stderr"
```

| Key | Type | Default | Behavior |
| --- | --- | --- | --- |
| `logging.level` | string | `"info"` | `trace` / `debug` / `info` / `warn` / `error`; tolerant — an unfamiliar value (e.g. `"verbose"`) does not break startup and is kept as-is. |
| `logging.format` | string | `"console"` | `console` or `json`; tolerant. |
| `logging.output` | string | `"stderr"` | `stderr` or `stdout`; tolerant. |

Logging is emitted via `tracing` in the `cli` crate only — the library crates stay logger-less.

### `dataset`

```yaml
dataset:
  name: ""
```

| Key | Type | Default | Behavior |
| --- | --- | --- | --- |
| `dataset.name` | string | `""` | The active dataset: per-dataset artifacts (ontology, content, knowledge DB, vector index) live under `<workspace_dir>/datasets/<name>/`. An **empty name means NO dataset** — the server runs with no data (no ontology load, no ingestion/indexing). `edtech` is not a default; only presets that ingest the demo corpus set it. `--dataset NAME` overrides this key for a single run. |

### `paths`

```yaml
paths:
  workspace_dir: "workspace"
  migrations_dir: "migrations"
  prompts_path: "workspace/configs/prompts"
  onnx_config: "workspace/configs/onnx.yaml"
```

| Key | Type | Default | Behavior |
| --- | --- | --- | --- |
| `paths.workspace_dir` | string | `"workspace"` | Workspace root for the global artifacts (models, onnxruntime, cache DB, and the `datasets/` tree). The global cache DB is `<workspace_dir>/db/cache/cache.db`. |
| `paths.migrations_dir` | string | `"migrations"` | SQL migration files, applied in order at startup. |
| `paths.prompts_path` | string | `"workspace/configs/prompts"` | Prompt template files (`.tmpl`); embedded defaults are used as fallback. |
| `paths.onnx_config` | string | `"workspace/configs/onnx.yaml"` | Path to the external `onnx.yaml` model/runtime registry. |

The legacy keys `paths.data_dir`, `paths.documents_dir`, and `paths.global_config_path` from the pre-restructure layout are accepted but ignored — the storage layout is now `paths.workspace_dir` + `dataset.name` (see [Workspace Layout](../concepts/workspace-layout)).

## The `onnx.yaml` model registry

The registry is an **external file** referenced from the preset via `paths.onnx_config` (default `workspace/configs/onnx.yaml`). It is the single source for the ONNX runtime library and every downloadable model; a missing or unparseable file fails loading with the file path. Unknown keys are ignored.

```yaml
runtime:
  version: "1.28.0"
  platforms:
    - key: "linux-amd64"
      os: "linux"
      arch: "amd64"
      archive_url: "https://github.com/microsoft/onnxruntime/releases/download/v1.28.0/onnxruntime-linux-x64-1.28.0.tgz"
      archive_format: "tgz"
      library_name: "libonnxruntime.so.1.28.0"
      library_path: "onnxruntime-linux-x64-1.28.0/lib/libonnxruntime.so.1.28.0"

models:
  default: "bge-small-en-v1.5"
  entries:
    - name: bge-small-en-v1.5
      display_name: "BGE Small English v1.5"
      description: "Lightweight BGE model for English text embeddings"
      version: "1.5.0"
      vector_dim: 384
      files:
        - name: model.onnx
          url: "https://huggingface.co/BAAI/bge-small-en-v1.5/resolve/main/onnx/model.onnx"
          size_bytes: 133093490
        - name: tokenizer.json
          url: "https://huggingface.co/BAAI/bge-small-en-v1.5/resolve/main/tokenizer.json"
          size_bytes: 711396
```

| Key | Type | Behavior |
| --- | --- | --- |
| `runtime.version` | string | ONNX Runtime version (the shipped registry: `1.28.0`). |
| `runtime.platforms[]` | list | One entry per platform: `key` (lookup key, e.g. `"linux-amd64"`), `os`, `arch`, `archive_url` (release archive to download), `archive_format` (`"zip"` or `"tgz"`; tolerant), `library_name` (library file inside the archive), `library_path` (path relative to the archive root). The shipped registry has 5 platforms: `windows-amd64`, `linux-amd64`, `linux-arm64`, `darwin-amd64`, `darwin-arm64`. |
| `models.default` | string | Name of the default model — what `synopsis model download` fetches. The shipped registry: `bge-small-en-v1.5`. |
| `models.entries[]` | list | One entry per model: `name` (registry name used by `embeddings.local.model_name`), `display_name`, `description`, `version`, `vector_dim` (embedding dimension), and `files[]` — each with `name`, `url` (download URL), `size_bytes` (exact size, verified after download), and an optional `checksum` (`"sha256:hex"`). The shipped registry: `bge-m3-int8` (1024-dim), `bge-small-en-v1.5` (384-dim), `paraphrase-multilingual-MiniLM-L12-v2` (384-dim). |

Every download is verified by **URL + size + SHA-256** (the size check is enforced after download; the `sha256:` checksum applies where a registry entry provides one). The full `model` and `onnx-runtime` command reference is in [Model Management](./model-management).

## Prompt templates

The LLM prompts for NER and cross-domain entity linking are **minijinja** templates. Overrides live under `paths.prompts_path` (default `workspace/configs/prompts`):

```
workspace/configs/prompts/
├── entity-linker/
│   ├── system.tmpl
│   └── user.tmpl
└── ner/
    ├── system.tmpl
    └── user.tmpl
```

A present `{system,user}.tmpl` file overrides the embedded default (and is noted in the run's notes); a **missing file silently falls back** to the embedded default in `crates/graph` / `crates/ingestion`. The shipped files are byte-identical to the embedded defaults, so they exist for visibility and editing — not for correctness.

## The XML ontologies

Ingestion sources and the entity/relation vocabulary are **not** in the YAML preset — they live in the dataset's XML ontology: `global.xml` (the global pool: entities, relations, extraction rules, sources, cross-domain linking methods) plus one file per domain under `domains/`. A missing or malformed domain XML is a **startup error**; a missing `global.xml` is not (the global pool is simply empty). The [Domains](../concepts/domains) page covers the file formats and the two-layer resolution.
